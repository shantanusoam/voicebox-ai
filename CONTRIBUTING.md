# Working on CallBox

Use a feature branch. Install development requirements, run pytest, inspect the server-backed console, then add a regression test for the change. Keep transport, business tools and provider code separate. Prefer small, reversible changes. The project intentionally avoids frontend build dependencies for easy inspection.

For bugs, report OS/Python/browser, reproduction steps, expected versus actual behavior and a sanitized log. Do not attach patient records, API keys, tokens or raw customer recordings. Hardware reports must identify the exact chip/board, SDK, phone model/OS and carrier; a board-family name alone is insufficient.

Do not add speculative revenue, latency, compatibility or clinical-safety claims to the website. Scores in the review report are scoped self-assessment, not certification.
