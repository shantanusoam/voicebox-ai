# Instructions for coding agents working in this repository

Read README.md, docs/ARCHITECTURE.md and docs/SECURITY.md first. Run the baseline tests before modifying behavior. Never claim a physical device, carrier, provider, browser or deployment was tested without a corresponding real execution result.

Run `python scripts/verify.py` before and after changing behavior: it gates every layer (config, source, domain/API, provider, gateway, firmware, hardened deployment, behavioral evals) and writes qa/verify-report.json. Add `--with-browser` when touching the console. New behavior needs a case in evals/ as well as a test. Paid API calls, real calendars, customer data, public deployment, hardware flashing and outbound calls require explicit operator authorization. Keep .env, .runtime, SQLite files and tokens out of commits and release archives.

Preserve deterministic confirmation, transactional slot rechecks, request-id/payload binding, bounded queues, per-call isolation and truthful integration status. Do not convert an unimplemented integration into an enabled UI status merely to make a demo look complete. Mock tests and relay-browser tests must keep their labels. Every new provider/transport needs contract tests, failure tests and a documented live-validation gate. Provider adapters go behind build_provider() and keep the transcribe/classify/speak interface so no other module learns which provider is configured. Never let a model's own report of 'no speech' be the only thing standing between silence and a committed action: gate it deterministically first.
